## 2. Catchment Estimation Approach

The system estimates the catchment area (drainage basin) for potential pond locations using a multi-stage geospatial pipeline that transforms raw contour lines into a hydrological model. The approach mimics physical water flow over terrain:

1.  **Interpolation**: Raw KML/KMZ elevation contours are parsed and converted into a dense 3D point cloud. This point cloud is then rasterized into a regular 2D grid called a Digital Elevation Model (DEM) using inverse distance weighting.
2.  **Hydrological Conditioning**: Real-world terrain contains local depressions (sinks) where water would become trapped, preventing continuous flow routing. The DEM is "conditioned" using a standard sink-filling algorithm, which raises the elevation of these pits to their pour-point elevation.
3.  **Flow Direction (D8)**: For every cell in the conditioned DEM, the D8 (Deterministic Eight-Node) algorithm determines the steepest downward slope among its 8 neighbors. This creates a grid representing the path a drop of water would take from any point.
4.  **Flow Accumulation**: By tracing the flow direction network from top to bottom, the system counts how many upstream cells drain into each specific cell. High-accumulation cells represent natural streams and valleys.
5.  **Pond Siting**: Potential pond locations are identified by finding areas with high flow accumulation (ensuring sufficient water supply) and low topographic slope (reducing excavation costs).
6.  **Catchment Delineation**: Once the optimal pond site is selected, the system performs a reverse Breadth-First Search (BFS) upward through the flow direction grid, identifying every single cell that eventually drains into the pond. This cluster of cells forms the catchment mask.
7.  **Area Calculation**: The mask is vectorized into a GeoJSON polygon. The exact area in hectares is calculated deterministically from the DEM resolution and the number of cells in the mask.

## 4. API Documentation

The complete OpenAPI documentation is auto-generated by FastAPI and available interactively via Swagger UI.

**Endpoint Summary:**
- `POST /analyzeContour`: The main pipeline entry point. Upload a `.kml` or `.kmz` file containing elevation contour lines to receive ranked pond candidates and the delineated catchment.
- `GET /health`: Used by load balancers and orchestrators to verify the API service is responding.
